# 大型结构健康监测与疲劳寿命评估服务

纯后端 Node.js + TypeScript + Fastify 服务，无需 Docker、数据库或消息中间件即可本机运行。

## 复杂业务闭环

- 基于本地 ENU 米制坐标的结构、构件和传感器模型
- 应变、加速度、位移、倾角和温度时序采集
- 采样质量、阈值告警、告警确认和检修证据闭环
- 模态频率漂移和阻尼比分析
- 应力序列、简化雨流计数、Miner 损伤和剩余寿命估算
- 车辆、风荷载和温度场景仿真（场景必须关联目标构件，按构件截面/材料/跨度/容许应力/疲劳细节计算）
- 构件健康指数与检查任务门禁

## 荷载场景与检修闭环

1. `POST /api/load-scenarios` 创建草稿，`elementId` 必填（不关联构件拒绝创建）；`PATCH` 可修改输入或目标构件。
2. `POST /api/load-scenarios/:id/simulate` 按关联构件属性计算峰值应力、位移、等效应力幅/Miner 损伤；命中风险规则（应力/位移/疲劳）时自动创建对应检修任务，结果可直接交付检查人员。
3. 结果带输入+构件归一化指纹：同一输入重复模拟复用未关闭任务，不重复建单；输入或目标构件变化后旧结果立即标记 `stale` 并回退草稿，不能再用于关闭任务。
4. `POST /api/inspections/:id/close` 两种关闭依据：证据齐备（不足返回 409），或 `closeWithResultId` 引用与当前输入/构件一致且该风险已消除的最新结果。
5. 保留草稿、已模拟和直接检修（`POST /api/inspections`，不经过模拟、只能凭证据关闭）三条流程。

默认端口：`6312`。

测试：`npm test`（覆盖不同构件、风险结果、重复模拟幂等、过期结果、证据不足、新结果关闭）。

## 模块结构

- `src/domain`：领域类型、坐标/单位约束和进程内状态锚点
- `src/services`：计算、仿真、融合和风险规则
- `src/routes`：按业务边界拆分的 HTTP 接口
- `src/app.ts`：应用组装与路由注册
- `src/index.ts`：进程启动入口

各模块保持单一职责，业务状态只由 domain state 模块持有，避免路由之间重复维护同一份状态。
